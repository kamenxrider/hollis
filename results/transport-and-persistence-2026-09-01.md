### Addendum (Phase 3, same day): UUID invocation verified

`shortcuts run` accepts the bridge **UUID** as the identifier, not just the name:

```bash
printf 'Reply with the single word: pong' \
  | shortcuts run BD8CDC56-7CB8-418D-9B02-9D33AB911BF0 --output-type public.plain-text
# stdout: pong (4 bytes, no trailing newline), exit 0
```

`shortcuts run <UUID>` therefore works, which is what this test set out to
establish.

**Superseded:** hollis originally referenced bridges by UUID with names kept
only for display. It now resolves the other way round — config override, then
a name match from `shortcuts list`, and the compiled UUID only as a reference
that is never treated as evidence the bridge exists. Those UUIDs are artifacts
of this machine; on any other Mac they name nothing.

## Test 4 — empty input (THE ONE FAILURE)

```text
printf '' | shortcuts run <bridge>       -> hung, killed at 60s, exit 142
shortcuts run <bridge> < /dev/null       -> hung, killed at 60s, exit 142
```

Both produced zero bytes on stdout and stderr and never returned. This is Apple's
documented warning materializing: a shortcut awaiting input pauses the command-line
process. There is no built-in `timeout` on macOS.

Requirements this imposes on the gateway:

1. Reject empty prompts locally, before invoking the runner.
2. Always run the child under a context deadline and kill the process group on expiry.
3. Never rely on the shortcut to fail on its own.

`SIGALRM` did terminate the process cleanly; no orphaned `shortcuts run` processes
remained afterward (`pgrep -fl "shortcuts run"` -> none).

## Test 6 — real failure surface

```text
missing shortcut     exit 1   stderr: Error: The operation couldn’t be completed. Couldn’t find shortcut
invalid output type  exit 64  stderr: Error: The value 'not.a.real.uti' is invalid for '--output-type <output-type>'
```

Real failures **do** produce nonzero exits and useful stderr, so the error model in §23
is implementable. The dangerous case remains success-shaped: exit 0 with empty stdout,
which is what a successful run looks like when stdout is a TTY.

Roughly 0.9s and 1.15s. The plan's provisional 120s timeout is ~100x the observed p50.
