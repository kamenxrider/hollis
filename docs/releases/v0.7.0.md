# Hollis 0.7.0

**Not released.** The tag exists, but release checks failed before any assets
or GitHub release were published. See [Hollis 0.7.1](v0.7.1.md) for the correction
and the carried-forward release content.

Runtime and plugin versions are separate. Each has its own archive and
evidence. Plugin 0.4.0 targets this runtime; its checked-in lock still pins
0.4.0 and blocks setup and packaging until verified published assets are pinned.

## Installation and guides

- The script installer retains the full bundle under
  `~/.local/share/hollis/<version>/` and links both executables into
  `~/.local/bin`. Later `hollis setup --import` can find its manifest and bridges.
  Upgrades replace older plain files or managed links without rewriting an
  existing version folder.
- Start with the [user guide](../getting-started.md) or the
  [Claude Code and Codex quick start](../../plugins/hollis/docs/quickstart.md).
  [Verification](../verification.md) distinguishes checksum-only downloads
  from source-commit verification with `gh`.

## Highlights

- Clearer Shortcuts errors. Device limits, content refusals and Cloud Pro
  account access have distinct codes, sanitized Apple diagnostics and HTTP
  statuses. Usage-limit output is never an answer, and provider limits never
  trigger automatic retry or fallback.

- A prepared Homebrew formula and a local-first quick start. After the formula
  is published, `brew install kamenxrider/tap/hollis` installs the matched CLI
  and native helper. The quick start begins with
  `hollis doctor --model local` and the on-device model, with no Shortcut import.
- Faster everyday use. `hollis "prompt"` works without `respond`, `hollis chat`
  answers `help` and `quit`, root help ends with examples, environment and exit
  codes, and `hollis examples` prints copyable job recipes.
- PDF text and OCR extraction. `--file report.pdf` reads the text layer on
  your Mac, with on-device OCR for scanned pages, and `--pages` selects pages.
- Single-image input on local. The on-device model accepts one PNG or JPEG
  image through the CLI and both HTTP endpoints, complete or streaming.
- Tool calling on local. Caller-provided tools through `respond --tools` and
  both HTTP endpoints, with `auto`, `none`, `required` or a named function, and
  up to eight model decisions per request including the final answer.
- Sampling on local. `--temperature`, `--top-p`, `--max-tokens` and `--seed`
  on the CLI, and `temperature`, `top_p`, `seed` and `max_tokens` /
  `max_output_tokens` over HTTP.
- MCP client. Attach MCP servers to `local` requests, as local programs over
  stdio or remote servers over HTTP, with per-call approval (`ask`) or an
  explicit allow list (`auto`).
- Opt-in partial MCP results. Oversized Local results stop by default,
  without truncation, with exit 5 and code `tool_result_too_large_for_local`.
  The message gives the full byte count and suggests `--partial-results`.
  JSON includes `error.suggestion`, including in automated calls.
  `--partial-results` or `hollis config set partial-results on` allows
  disclosed prefixes with stderr notices, JSON `tool_results_bounded`, and
  private full-result files at mode 0600. Normal approval and validation
  remain required. A partial answer can miss essential evidence.
  HTTP and batch still execute no MCP tools.

## Changes

- Four `AFM Bridge JSON - <Route>` Dictionary bridges provide `public.json`
  transport for `--format json` and API `json_object` (Responses uses
  `text.format`). On success Hollis returns one validated JSON object;
  invalid output fails explicitly with `invalid_json_output`. A request can
  still fail or return wrong data. Shortcut routes do not enforce requested
  fields, types or values: models may add keys, use `false` or `"null"` instead
  of null, nest answers or change punctuation. Local `--schema` / `json_schema`
  constrains structure and types to the supported schema subset, not factual
  correctness. Missing JSON bridges retain text behavior with an import
  hint and a doctor warning. Route imports include both bridge variants;
  `-json` selects only the JSON variant. Text transport remains unchanged.
  Shortcuts may spell 19.95 as `19.949999999999999`; Hollis preserves that spelling,
  so financial or exact-decimal callers should use decimal strings or round explicitly.

- `respond --format json` validates one JSON object on Shortcut routes, accepting
  an optional whole JSON fence but never prose, arrays or repaired fields.
  Chat Completions supports the same behavior with `response_format` type
  `json_object`. Invalid output is `invalid_json_output` (CLI 5 / HTTP 502),
  with raw output in machine errors and no retry. Local CLI uses `--schema`;
  Local HTTP JSON-object behavior is unchanged.

- Doctor warns when exact bridge names are duplicated, with JSON reason code
  `duplicate_bridge_name`. Forced imports warn that replacing can leave
  duplicates; no route or Shortcut is changed automatically.

- Setup asks for Add Shortcut approval only when it opens import windows.
  If the selected bridges are already installed, it reports that nothing
  needs importing.

- Shortcut routes now place explicit and conversation system/developer
  instructions after replayed conversation context, including continued chats,
  shortened context, HTTP requests and image conversation prompts. This is
  instruction placement, not an instruction-following fix or an isolation
  boundary. Native Local framing is unchanged.

- Shortcut setup now supports explicit bundled imports with route selection,
  consent, installed-bridge discovery, manifest checksum verification and private
  signed copies. Apple's Add Shortcut approval remains manual.

- Publish v0.7.0 first. The curl installer stays unavailable and refuses
  installation until a follow-up sets the authenticated bundle SHA-256
  fingerprint and source commit pins; the current hash is empty and the source
  pin is stale. Once pinned, it checks the SHA-256 plus release checksums
  without `gh`, or also verifies build attestations with `gh`. The Homebrew
  formula and plugin runtime pins also await authenticated published assets
  and follow-up updates. The prepared formula includes an optional
  loopback-only background API service with token-file configuration documented.

- Plugin 0.4.0 updates the shared skills for context controls and validates
  portable Agent Plugins manifest and skill discovery. Its runtime pins still
  need verified published 0.7.0 assets before setup or packaging.

- Contributor documentation adds `AGENTS.md` and an offline documentation link
  checker alongside the full build and verification guide.

- Hollis adds opt-in conversation context strategies: strict remains the default,
  while drop-oldest, sliding-window and Local-only summarization shorten individual
  requests without changing stored history. Local fitting uses native token counts
  and the existing answer reserve. Omitted messages are disclosed in human notes
  and JSON, and a preferred strategy can be saved through config.

- Respond and chat now support opt-in retry on Local only: bare `--retry` allows
  three extra attempts, while `--retry=N` selects up to five. Only transient model-busy
  failures retry, before output or tool activity, using interruptible exponential
  backoff within the original timeout. Quiet mode hides retry notes, and successful
  JSON responses disclose the CLI attempt count. Other model routes, image
  generation, batch and HTTP behavior remain unchanged.

- Hollis adds `hollis update`, an explicit, ten-second check for the latest stable
  GitHub release, with semantic-version comparison, installation-specific upgrade
  guidance and JSON/agent output. There are no automatic checks. Homebrew
  installations can opt into `--apply`, with confirmation or explicit `--yes`;
  installer and manual installations receive instructions only. An available
  update exits successfully, and newer development builds are never offered a
  downgrade.

- `hollis benchmark` measures native Local with fixed, built-in prompts and serial
  calls, without saved chats or network requests. It separates the first call from
  warm runs of short text, streaming, guided JSON and token counting, reporting
  median and p95 times, first-text latency and throughput only from measured SDK
  usage. Human and JSON/agent output keep failed attempts visible, omit generated
  answer text and report partial results on cancellation. Runs are bounded and
  never retry or fall back.

- Bare terminal invocation prints short help without reading stdin. Full help
  uses web links and names the issue tracker. Respond/chat add terminal-only
  delayed waiting notes, suppressed in machine, quiet and no-input modes.
  `-m` selects a model on respond, chat and batch plan; `-f` attaches a document
  on respond. Agent context reports flag shorthands.

- `respond` adds native Local instructions (`--system`/`-s`, `--system-file`),
  one-shot OpenAI conversations (`--messages`), model-free native token
  counting (`--count-tokens`) and opt-in permissive text transformations.
  Shortcut routes receive instructions as labelled text after the prompt,
  without guaranteeing instruction following; this is not a separate
  instruction channel. `--quiet`/`-q` hides notes without hiding answers or errors.

- Chat Completions accepts harmless OpenAI app fields (`n:1`, disabled log
  probabilities and an ignored, unstored `user` label). Local streams can opt
  into a final usage chunk. Local also supports validated, complete-only
  `response_format:{"type":"json_object"}` without a schema.

- Batch Cloud calls now wait 30 seconds after completion to reduce the risk of Apple's per-Mac cloud blocks, which can last hours; pacing cannot guarantee access. Cloud Pro stays at 45 seconds, ChatGPT at 15 seconds, and Local remains unpaced.

## First-run diagnostics

Model discovery includes unavailable routes and marks the configured default.
Native diagnostics distinguish unsupported platforms, unknown availability,
helper identity mismatch and malformed protocol data without extra CLI probes
on `models --model local`. Doctor suggests a next action without diagnostic
loops or selecting another installer. Native repair guidance preserves the
original installation source and the matching CLI/helper pair.
Empty chat lists and no-match searches include human-only next-step hints.

## Embedded job recipes

`hollis examples` prints copyable, job-organized recipes without running them.
The same embedded guide supports human, JSON and agent output, and every
displayed shell block runs verbatim in offline tests with synthetic model
runners. See [the recipes](../../examples/recipes.md) and
[their test scope](../testing.md#copyable-job-recipes).

## Config defaults and diagnostic exit behavior

`config get` and `config unset` inspect or remove one saved setting.
`config set timeout` saves a duration for respond, chat and image generation.
Explicit options override `HOLLIS_MODEL` / `HOLLIS_TIMEOUT`, which override
saved values. Continued chats keep their stored model; batch and HTTP defaults
are unchanged. Saved `auto` now selects Cloud for image input like an unset
model, while explicitly requested `auto` remains refused.

**Compatibility change:** plain `doctor` now exits 0 as an overview even if
routes are unavailable. Use `doctor --model <route>` as the nonzero readiness
gate. Overview JSON/agent output explicitly says readiness was not assessed
and carries diagnostics rather than a top-level error envelope. `--select`
cannot remove those overview markers. Plain `setup` prints route help; its
selected standalone form explains that unverified files do not imply a
missing helper. See [CLI usage](../cli.md).

## Database schema v3

> **Changing back to an older Hollis binary does not undo this upgrade.**
> Runtime 0.4.0 supports schema v2 only and refuses a v3 database with a
> newer-schema error and exit 10. A plugin pointer, a reinstalled package or an
> older executable does not downgrade the data or restore a backup. Recover
> deliberately, with the [database upgrade and recovery steps](../cli.md#database-upgrades-and-recovery).

Schema v3 adds an indexed UTC nanosecond key for chronological chat listing.
Readable timestamps and stored transcripts are preserved. Malformed timestamps
or instants outside the signed 64-bit nanosecond range (approximately September
1677 to April 2262) stop the upgrade instead of inventing a timestamp.

The migration is atomic: schema changes, backfills, search-index recovery and
the schema-version update commit together, and a failed migration rolls back its
uncommitted changes. Before migrating or repairing an existing database, Hollis
retains a private `.hollis.db.backup-*` SQLite snapshot in the state directory.
The snapshot includes committed WAL data at that moment; it does not promise to
capture later writes from an already-running process. The migration lock
coordinates compatible Hollis openers, not simultaneous old and new runtime use.

## Strict field selection

`--select` now validates against the command's declared schema before any model
call or other command work. Unknown fields and malformed paths fail with a
usage error, exit 2, instead of being silently omitted. This is an intentional
correction to earlier lenient behavior; valid optional fields may still be
absent, and fields that occur only in later array rows stay valid.

## Selected-route setup and diagnostics

`hollis setup --model <route>` plans setup for one concrete route, and
`hollis doctor --model <route>` inspects only that route. Both are described in
[selected-route setup and diagnostics](../selected-route-setup.md).

Plans report a route-scoped status such as `ready`, `import_required`,
`approval_required`, `model_not_ready` or `unknown`, with a reason code, explicit
actions and `inference_tested: false`. Selected doctor reports
`artifact_verification: "unknown"`. An installation that cannot present a fresh
verified-runtime record, including standalone, source, `go install`, direct and
Homebrew invocations, receives an action-needed `runtime_unverified` result and
can still use selected doctor for read-only availability diagnostics.

These checks never request inference, import Shortcuts, download artifacts,
change permissions or change Apple settings. A ready prerequisite is not a
successful inference, and a failed listing does not prove a bridge is missing.

## Bounded Shortcuts output

Every Shortcuts run has an effective deadline and a bounded output capture. A
run whose stdout exceeds the 1 MiB capture cap is refused as a transport
failure, exit 5: the response cannot be delivered faithfully, so Hollis does not
return a partial one. `shortcuts list` uses the same 1 MiB bound and reports an
oversized listing as a transport failure, exit 5, rather than proving a bridge
missing or inventing bridge names. Stderr keeps a bounded head and tail so a
late diagnostic can still classify the failure. See
[Shortcuts transport](../shortcuts.md#how-it-works).

## Native local: protocol 4, helper 0.7.0 and guided output

CLI model/doctor capabilities and API `/v1/models` now share `backend`,
`streaming`, `complete_usage`, `stream_usage`, `images`, `max_images`,
`guided_output` and `tools`. Local tools follow the helper's executable
turn-handoff advertisement. For this release the API keeps its older `usage`,
`streaming_usage` and `image_input` names as extra copies of `complete_usage`,
`stream_usage` and `images`, respectively, for existing clients.

`hollis respond --schema` asks the on-device model for a JSON object that
conforms to a supported schema subset. Guided output needs the `local` route, a
protocol-4 helper (`hollis-native` 0.7.0 matches this release) and
`capabilities.guided_output: true` from `hollis models --model local --json`.

Protocol 3 added negotiation, capability advertisement and named refusal; protocol 4
adds the executable tool turn handoff. Hollis 0.7.0
supports caller tools and one PNG/JPEG image on local, separately. Native image
input requires macOS 27 and a vision-capable model, works through CLI and both
HTTP endpoints in complete or streaming mode, and refuses tools/images and
guided-output/images combinations. Capability advertisement is not proof of
runtime availability or successful inference.

`hollis respond --file` now accepts PDFs. The paired native helper reads
them on this Mac through the helper's `extract` operation: the text layer per
page, with on-device OCR for pages that have none, and no model call. Content
decides the route, not the extension. `--pages` selects pages of one PDF.
New error codes: `invalid_document`, `extract_no_text`, `unsupported_media`,
`extract_media_mismatch` and `page_out_of_range`; extracted text over 128 KiB
is `context_capacity` with both numbers. See [text documents](../cli.md#text-documents).
OCR uses Vision's accurate recognition. Only if that request fails does Hollis
retry the page with fast recognition, in four orientations, within the same
time limit; cancellation, timeouts and pages where nothing is found are never
retried. The fast backup is less reliable: it can miss a lone very short word,
can miss short text on a sideways page, and on an upside-down page it can keep
a garbled reading instead of the correct one.
The helper accepts request formats 1 through 4 but stamps all events with 0.7.0;
older CLIs reject that version. CLI and helper ship as one matched bundle, and
a mismatched pair fails closed with a clear error and matching-bundle remedy:
`native_protocol` (exit 5, HTTP 502), never a plain-text downgrade. The helper's
status event now carries `capabilities`. A request needing a capability that
the helper did not advertise is refused by name as `unsupported_capability`
(exit 5, HTTP 502), a component fault, not a caller mistake.

The subset accepts an object root and closed objects (`additionalProperties`
`false` or omitted, which means `false`); `string`, `integer`, `number` and
`boolean` properties; `required` naming declared properties; string enums;
arrays with `items` and `minItems`/`maxItems`; integral integer bounds and
finite number bounds; printable-ASCII names; at most three object levels,
sixteen schema nodes on any path, 32 properties and 64 KiB normalized.

It also accepts the keywords real tool and API schemas carry. Annotations
(`description`, `title`, `$schema`, `$id`, `$comment`, `default`, `examples`,
`deprecated`, `readOnly`, `writeOnly`, `x-` keys) are ignored for validation,
and `description` or `title` is passed to the model. String constraints
(`format`, `minLength`, `maxLength`, `pattern`, `contentEncoding`,
`contentMediaType`) are accepted and **not enforced**: Hollis checks the type
only. A nullable `anyOf`/`oneOf` property (one schema plus `null`) is treated as
that schema, optional, with `null` accepted. **A `default` is never applied.**
This is a compatible relaxation: every schema accepted before is still accepted
and validated identically.

References, recursion, `allOf`/`not`, other unions, `const`,
`additionalProperties` other than `false`, integer enums, duplicate keys and
contradictions are rejected before any process spawns, with exit 2 naming the
offending JSON pointer. Nothing is inferred in that case.

Guided output is complete-only: `--schema` refuses `--stream`, `--image` and
every route except `local` before generation. A returned object is re-validated
independently, and a failure is an error rather than a partial or repaired
object. Structural validity does not make the content true.

Complete native responses report Apple's measured `usage`, and `models`/`doctor`
report `context_size` when the helper provides it. On 2026-11-01 one Apple
Silicon Mac reported an 8,192-token window for the on-device model. That is a
dated observation of one setup, not a guarantee for other builds, models or
future requests. Responses streaming usage remains unreported; Chat Completions
can opt into a final usage chunk with `stream_options`, with null when counts
are unavailable.

## Guided JSON output over HTTP

The same guided path is reachable through `/v1/chat/completions`
`response_format` and `/v1/responses` `text.format`, with OpenAI's `json_schema`
shape. Only `model: "local"` supports it, and there is no silent fallback to
plain text. The schema is validated before capacity is taken or a helper
spawns: an unsupported schema is **400** `invalid_schema`, and `stream: true`,
image input, a non-local model or an unsupported `response_format` type is
**400** `unsupported_parameter`. The returned object is a JSON string, re-validated
by Hollis, and a validation failure is **502** `native_protocol`. Details are in
[guided JSON output](../api.md#guided-json-output).

## Caller-provided tools on local

Hollis 0.7.0 adds `hollis respond --tools` and tools on both HTTP endpoints,
for `local` only. Chat Completions uses nested `function` definitions;
Responses uses flat function definitions. Schemas must fit the supported
subset, and every returned call is validated. The caller executes the tool
and sends back its result; Hollis never executes caller tools.

The matched protocol-4 helper registers executable Swift tools and advertises
`tools.executable` and `tools.turn_handoff`. Callbacks capture a complete native
batch and return it to Go for independent validation before approval or dispatch.
There is no Local text-call extraction, argument coercion, repair or fallback.
Tool choice supports `auto`, `none`, `required` and an exact named function.
Required allows dependencies after its first real call; named disables callbacks
after its selected result. Structured replay satisfies that obligation for the
current user transaction; a new user message resets it.

Tool requests are complete-only and refuse images or guided output. The default
budget is eight decisions including final synthesis and visible prior batches.
A batch on the final decision fails before dispatch. Stateless replay is not a
global quota. Definitions, complete history and framing count toward both byte
and SDK token preflight limits, without truncation.
Only a transient `model_busy` decision can retry once before callback capture
in that decision, with identical input and the original deadline; tool execution
never retries. This is not argument repair. Shortcuts and ChatGPT text protocols
remain unchanged.
See [tools over HTTP](../api.md#tools-on-local) and
[CLI tools](../native-local.md#tools).

Over HTTP, every call must be answered by a tool result before the next message
and before the history ends; an unanswered call is **400**. Responses output
items can be replayed as input as returned, including `type:"message"`, `id`,
`status` and empty `annotations`. A request the native loop refuses as a usage
error is **400** `invalid_request_error`, not a server failure. A supported
request is not a guarantee that the model calls the right tool.

## Sampling on local

`hollis respond` accepts `--temperature`, `--top-p`, `--max-tokens` and `--seed`
on `local`. Both HTTP endpoints accept `temperature`, `top_p` and a UInt64
`seed`, with `max_tokens` on Chat Completions and `max_output_tokens` on
Responses. Omitted fields keep the SDK defaults. Temperature is in 0..2 and zero
selects greedy decoding; top-p is in (0,1]; greedy combined with a seed or top-p
is refused. The token limit is Apple's approximate per-decision limit, not an
exact cap, and Hollis does not truncate output to enforce it. Sampling applies
to Local text, streaming, guided output and tool generation; other routes and
image generation refuse it before any model access. See
[local sampling](../api.md#local-sampling).

## One-image prompt wording

With exactly one attached image, a plural phrase such as "these images" in the
final user text is changed to its singular form, so the model does not look for
images that are not there. A human terminal shows the suggestion and asks
first; scripts, JSON and agent calls apply it, say so on stderr and add
`prompt_adjusted: true`. `--keep-prompt` on the CLI or `X-Hollis-Keep-Prompt: 1`
over HTTP sends the original wording; HTTP discloses an adjustment with
`X-Hollis-Prompt-Adjusted: true`. See [one attached image](../cli.md#one-attached-image).

## MCP client

`hollis mcp add`, `list`, `remove`, `mode` and `allow` manage servers in
`mcp.json`. `respond` and `chat` attach them to `local` only with `--mcp <name>`
or `--mcp-server`; nothing attaches by default, and `serve` and `batch` never
start a server. A server is a local program over stdio or an `https://` URL.
In `ask` mode, the default, every call shows its full arguments and runs only
after you approve it; `auto` runs only the exact tool names on an allow list.
Invalid native arguments stop with `tool_call_invalid` without a correction,
and an incomplete native batch fails closed before anything runs. Models see each
tool as `<server>__<tool>`. `mcp add --tool NAME` (or `mcp set --tool`) offers
only the named server tools. `--header NAME:VALUE` stores a non-secret HTTP
provider setting; credential-like names are refused, so credentials go through
`--auth`, which names an environment variable read when the server is contacted.
Credential-like query parameters in a server URL are refused for the same
reason. See [MCP servers](../mcp.md).

## Native helper mismatch over HTTP

At startup `hollis serve` asks the paired helper for its status without
generating anything. When the answer names a different protocol or version,
every `local` request, guided or plain, complete or streamed, is **502**
`native_protocol` with a message that the helper does not match this Hollis
version and a pointer at the matching bundle. A missing or unavailable helper
stays **400** `model_unavailable` at admission; a helper that fails mid-run is
**503** `model_unavailable`. See
[native local helper mismatch](../api.md#native-local-helper-mismatch) and
[failure meanings](../errors.md).

## AI pull-request review

The review workflow sends a bounded unified diff to `gpt-6-luna` with `xhigh`
reasoning effort over the documented Chat Completions shape. It sends only
text, with no tools or model command executor. A manual smoke run is available
from the Actions tab through
[`ai-review-smoke.yml`](../../.github/workflows/ai-review-smoke.yml); it runs
only on the default branch, makes a single synthetic request, keeps the
response as an artifact and never touches a pull request. See
[the review helper](../../scripts/ai-review/README.md).

## Background API and shell completions

A LaunchAgent template at `packaging/launchd/` runs `hollis serve` at login on
loopback with a token read from a private file; the plist never holds a token
value. [Running the local API in the background](../serve.md) covers loading,
unloading, restart behavior and the log location. Nothing installs or loads it
automatically. The installer's final message now names the completion setup
help for the login shell; it does not write completion files. See
[shell completions](../cli.md#shell-completions).

## ChatGPT route polish

**Changes:** too many images on any route is now HTTP **400**
`unsupported_parameter` ("model \"X\" accepts at most N image(s)"). Cloud,
Cloud Pro and ChatGPT previously returned 413 `context_too_large`, which
remains for byte and pixel limits. `/v1/models` and `hollis models --json`
report `capabilities.max_images` for each route. A tools request to a
Shortcuts route is refused for the route before its definitions are checked.
`setup --model chatgpt` names the System Settings switch for the ChatGPT
extension, and Ctrl-C during a Shortcuts request says "request canceled
(Ctrl-C); no response was returned", still exit 5. A ChatGPT timeout now
mentions that the request may be waiting for approval in a macOS prompt or
because **Confirm ChatGPT requests** is on, also in JSON `error.suggestion`.

## CLI fixes

- The CLI now enforces each route's image limit before anything is staged or
  sent: four images on Cloud or Cloud Pro are refused with "model cloud
  accepts at most 3 images", exit 2, `unsupported_parameter`.
- A timeout hint suggests a larger `--timeout` only below the 120-second
  ceiling; at the ceiling it no longer suggests one.
- `--help` and `-h` now show help and exit 0 for every command, including
  commands that need arguments, such as `hollis chats show --help` and
  `hollis mcp add --help`. Invalid arguments or flag values given alongside
  `--help` are still refused with exit 2.

**Changes:** a second image on ChatGPT or local is now refused with machine
code `unsupported_parameter` instead of `usage`, matching HTTP. The message
and exit code 2 are unchanged.

### Request safety and compatibility details

- Unauthenticated HTTP requests require loopback Host and Origin headers.
- MCP query names containing credential stems are refused, apart from explicit
  harmless exceptions; command views omit every URL path and query.
- Local token-limit termination uses a documented best-effort usage signal.
- Command-shaped quoted prompts and lone unknown kebab-case commands exit 2;
  `respond` and `--` remain literal escapes.
- Cloud-family requests have a bounded advisory PCC quota preflight. Only a
  reported limit reached blocks a request; available or unknown does not promise
  Shortcuts will succeed.
- HTTP validation errors no longer echo caller values, including schema
  pointers, function names or model names. CLI diagnostics retain their detail.
