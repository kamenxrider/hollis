# Hollis 0.3.1 — prepared, not published

Image-reference failures now explain whether a file is missing, inaccessible or
unreadable without repeating its local path in the answer. This applies to
direct generation and conversation references, including previous artifacts.
Error classification, exit codes, size limits, checksums and file protections
are preserved. Invalid references never reach the generator.

Ordinary source builds identify themselves as `dev`. Release builds continue to
receive their exact version through linker flags; both local Mac binaries were
built as `0.3.1` for validation.

## Validation

Full Go tests, race tests and vet passed. Focused regressions cover path-free
errors, zero generator calls, reference safeguards and both version contracts.
Twelve actual CLI process checks passed across direct/chat, human/agent and
missing/denied/other filesystem failures. Claude and Codex also completed four
serialized Apple calls with the local candidate, including an explicit image
reference follow-up. See the [closure report](../plugin-review-closure.md).

## Release sequence

These are local builds, not published or GitHub-attested assets. The unpublished
plugin remains `0.1.0`; its official runtime lock and preserved archive still
contain `0.3.0`. Installer readiness and rollback improvements belong to the
[plugin changes](plugin-v0.1.0.md), not this CLI binary.

After separate publication authorization, build and publish the 0.3.1 runtime,
verify its GitHub provenance, update the plugin lock, then rebuild and recheck
the complete plugin archive. Preserve the earlier archive and receipts.
