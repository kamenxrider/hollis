# Hollis 0.3.2 — prepared locally, not published

This update makes failed Apple requests easier to understand and prevents
runtime `auto` from issuing a second model call after an ambiguous failure.
Existing configuration, conversations and installed Shortcuts are preserved.

## Changes

- Apple's recorded failed-process “Try describing something different” message
  becomes `request_declined`. Its underlying cause remains unknown; Hollis
  does not label it a confirmed safety rejection or recommend reinstalling a bridge.
- Unrecognized unsuccessful Shortcut execution becomes `shortcut_failed`.
  Actual launch/transport problems remain separate.
- Direct commands, stored conversations and HTTP endpoints use the same
  distinction. New public failure messages omit raw process diagnostics.
  Numeric exit codes, HTTP statuses and JSON envelope structure remain stable;
  `agent-context` advertises the additional semantic codes.
- Runtime `auto` can fall back only after a confirmed missing bridge or recognized
  rate limit. Declines, unknown failures, empty output, timeouts, cancellations
  and crashes stop. Explicit model choices still never fall back.

See [failure meanings](../errors.md) for the command and HTTP contracts.

The companion plugin source also reports `runtime_path`, the binary-resolved
`config_path`, and structured discovery outcomes in `setup.sh status`. Failed
listing is unknown; a successful empty listing establishes absence. These
plugin changes are separate from the runtime binary and are not in the retained
0.3.1-backed archive yet.

## Validation

Full Go tests, race checks and vet passed, along with 50 plugin regressions,
30 image-harness tests, 22 review-boundary tests, three image-bridge tests,
four new journal/pacing tests, manifest validation and shell syntax checks.
Archive tests cover native `ditto` extraction, executable modes and integrity.
Subprocess regressions reproduce the decline and unknown-failure distinction,
test exact call counts, and preserve successful answers containing similar text.

The approved live programme made **44 serialized calls: 40 completed outputs
and four declined requests**, including eight targeted diagnostics. Text and
image-understanding tasks passed in Claude Code and Codex. All five generation
styles produced images during the round, but both coffee photo conditions were
declined twice. Any Style lighthouse controls succeeded as stylized images.

Both historical reference cases generated with and without attachments three
times each. Additional controls did not recover the attached subjects when
the prompt omitted them. Reliable reference editing therefore remains unproven;
the earlier declined reference request succeeded here, without establishing
the cause of its original failure. [Per-call evidence](v0.3.2-validation.json).

The minimum measured gap after completion was 10.000 seconds, and before
Cloud Pro it was 45.002 seconds. No rate limit, timeout, uncertain completion,
automatic retry or tier substitution occurred. This was an existing approved
Mac account, not fresh-account or first-consent proof. Hosts emitted absolute
image previews and fallback links; user-visible inline rendering was not
independently confirmed. Image Playground was not automated.

The 36-call matrix and seven image diagnostics used one frozen binary. The
final binary additionally preserves the legacy usage classification for an
exit-64 process carrying decline wording; full regressions and one final Cloud
smoke check passed on that final source/build. The measured build is retained.

## Delivery boundary

ARM64 and AMD64 binaries and checksums are prepared locally. They have no
GitHub release provenance yet and do not change platform compatibility.
Publication is a separate authorized step. After publication, verify provenance,
repin the plugin lock, rebuild its archive and repeat package acceptance.

The unpublished plugin remains 0.1.0 and its lock remains on verified runtime
0.3.1. Its existing archive and historical receipts are preserved. No claim is
made that the existing archive includes these changes.
